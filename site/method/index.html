信源核验标准

每一个数字，都要能追到一句话、一个页面、一个日期

案例墙 / 全部案例 / 信源核验标准

AI 让内容生产变便宜，也让「看起来像真的」变便宜。本站的核心差异不是案例数量，而是每条数据都能回溯到具体信源，并标明口径与核验等级。

为什么需要一套标准

一人公司题材有三个天然的信息陷阱：

  • 自述偏差：收入、用户数多由创业者本人提供，缺少第三方审计。
  • 转载放大：一篇采访被多个平台换标题转载，看起来像「多家媒体报道」，实际只有一个采访源。
  • 口径混用：流水与净利、GMV 与营收、注册用户与日活，常被放在同一句话里比较。

如果不做区分，案例墙就会变成「谁的故事更夸张谁排前面」。所以本站采用分级 + 标记 + 留痕的方式，把不确定性显式写出来。

信源分级：A- / B+ / B

等级定义典型例子
A-可回溯的一手记录：官方披露、工商与备案信息、平台公开数据、当事人完整访谈原文成都高新区官网通报、Steam 商店页与评测数、天眼查工商页、媒体署名深度访谈
B+主流媒体一手采访，或两个及以上相互独立的来源交叉印证央媒/党媒记者署名报道 + 另一家独立采访
B二手转述、平台榜单、单一来源、无法独立验证的第三方估算转载稿、自媒体拆解、销量估算站

为什么最高是 A- 而不是 A：一人公司的经营数据几乎不存在审计级公开记录，任何「A」都可能是过度自信。A- 表示「目前能达到的最高可回溯程度」。

三色标记：verified / cross / partial

  • verified（绿）：已核验，或至少两个独立来源一致。
  • cross（蓝）：多源印证，或存在单一权威来源且可回溯。
  • partial（黄）：部分映证、自述、转述，或存在口径冲突尚未解决。

标记出现在两个位置：正文引用角标，以及文末信源列表的编号色块。点角标可跳到对应信源，看到原始标题、媒体、日期、链接和核查说明。

当前 100 个案例的分布是：verified 23 例、cross 54 例、partial 23 例。黄色并不等于不可信，而是提醒读者：这条信息需要你带着保留意见阅读。

五步核验流程

第一步：检索，先找一手

优先找当事人署名的访谈、官方通报、平台原始页面。搜索引擎结果里排在前面的往往是转载与聚合，需要继续往下找原始出处。

第二步：锁定原始页面

确认标题、作者、媒体、发布时间、原文链接。转载稿不作为独立信源计数，即使它出现在十家平台上。

第三步：交叉关键数字

收入、用户、融资、销量这四类数字至少要有两个来源，或一个可回溯的原始记录。只有单一自述的，标 partial 并在正文写明「自述口径」。

第四步：对齐口径

把「月收入 / 年收入 / 合同额 / 流水 / 净利 / 单店 / 全公司」拆开，写清楚每个数字的统计对象与时间范围。不同媒体的口径冲突时，并列呈现，不取平均。

第五步：留痕与复核

每条信源保留编号、评级、类型、标题、来源、日期、链接与核查说明；文末用一段小结说明「实质独立信源有几个」。数据随时间变化，重要案例会定期回看。

这些字段不只写在页面里，也汇总为一份公开的信源台账：1,184 条信源逐条记录 URL、发布方、日期、核验等级，以及该信源在正文中支撑的具体句子，便于读者与研究者独立复核。

口径冲突怎么处理

举个站内真实例子：某 AI 呼叫系统创业者的报道，标题写「年入百万」，正文写「营收近百万元」。标题是编辑提炼，正文是受访者原话，两者不一致。本站采用正文口径，并在报告中单设说明，而不是直接引用更吸引眼球的标题。

类似地，估值「过亿」若只来自企业提供的投资资料，就标注为企业口径；「准确率接近 100%」若只在单一样本上成立，就明确说明不可外推。处理原则只有一条：宁可写得保守，也不把不确定写成确定。

明确不做的事

  • 不编造信源、链接、记者姓名或发布日期。
  • 不把第三方估算写成官方披露，例如把销量估算站的数据当成实际销量。
  • 不替未公开姓名的当事人编名字，改用「00 后脑瘫博士」这类可核验的描述。
  • 不把创始人自述包装成第三方证实，正文必须出现「自述」二字。
  • 不用转载数量冒充独立信源数量。

局限与纠错

这套标准解决的是「可回溯」，解决不了「绝对真实」。仍有三类风险：平台数据可以刷、媒体采访可能带有宣传目的、时间会让数据过期。因此每篇报告都标注时间锚点，读者应把它理解为「某个时点的公开记录」，而不是实时状态。

如果你发现事实错误、链接失效或口径误读，欢迎通过站点仓库提交 issue，我们会核对后更新，并在报告中保留修订说明。
