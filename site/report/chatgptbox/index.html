案例档案

Case Profile

chatGPTBox 是「浏览器即 AI 入口」路线的代表性开源作品：任意网页按 Ctrl+B 呼出对话浮窗，划词即可翻译、总结、解释代码，无需在 ChatGPT 网站与当前页面间来回切换。由独立开发者 josStorer 一人发起并维护至今，以 MIT 协议开源、完全免费、BYOK（用户自带 API Key 或账号会话）为基本姿态。

产品
浏览器扩展 chatGPTBox（「Deep ChatGPT integrations in your browser, completely for free」）：任意页呼出对话框（Ctrl+B）、右键总结整页（Alt+B）、独立会话页、划词工具（翻译/总结/润色/情感分析/段落划分/代码解释）、搜索引擎与常用站点（Reddit、YouTube、GitHub、知乎、B 站等）集成、视频总结、多分支会话卡片、记录保存、代码高亮与公式渲染。

创业路径复盘

Key Turns
转折一：从「搜索框挂 AI」到「全浏览器挂 AI」的形态跃迁
前身 chatGPT-search-engine-extension 只做一件事——把 ChatGPT 回答挂到 Google 搜索结果旁。2022-12-14 分离独立后，josStorer 把集成面从「搜索引擎」推进到「任意网页」：浮动窗、划词气泡、右键菜单、站点适配、独立会话页层层叠加。这说明 chatGPTBox 不是灵光一现的 MVP，而是同一个作者对「AI 应该长在哪里」的第二次、也是更深一次的回答。[1]
转折二：完全免费 + BYOK + 可自证的隐私承诺，构成产品哲学
商业插件普遍走「免费额度 + 订阅」路线时，chatGPTBox 选择彻底不碰钱：模型费用由用户自带（账号会话或 API Key），第三方检测确认无任何付费功能。配套一条少见的隐私声明——「本扩展不收集你的数据，你可以在代码里全局搜索 fetch( 与 XMLHttpRequest( 自行验证所有网络请求」，并默认手动激活、不主动上传页面内容。对个人开发者而言，「不收钱」反而是最低成本的信任构建方式。[1][4]
转折三：一个人顶住三年半的五端维护
浏览器插件是「苦力活」：双引擎、Manifest V2→V3 迁移、Safari/Android 移植、AI 服务商接口漂移、目标网站改版致适配失效。chatGPTBox 的解法是工程化——CI 自动发 Release（v2.7.2 即由 github-actions 发布）、站点适配与划词工具模块化可开关、扩展接口文档化。但 228 个 open issues 与单周增长归零的商店曲线提示：个人维护已进入「稳态维生」而非「高速增长」阶段。[3][11][4]

This extension does not collect your data. You can verify it by conducting a global search for `fetch(` and `XMLHttpRequest(` in the code to find all network request calls.

—— chatGPTBox README「News」首条，作者 josStorer（2026-11-13 抓取），[1]

产品与商业模式

Product & Model

chatGPTBox 的产品逻辑一句话：把 AI 的调用成本压到「零切换」——AI 动作长在浏览器的每一个交互原语上（快捷键、右键、划词、搜索框、站点页面）。

维度内容说明 / 信源
产品功能（集成形态）① 对话：任意页 Ctrl+B 浮窗、独立会话页、多分支会话卡片；② 划词工具：翻译、总结、润色、情感分析、段落划分、代码解释、自定义提问；③ 页面/视频：右键总结整页、YouTube 视频总结、B 站/知乎等站点适配；④ 搜索：全主流搜索引擎结果页集成 + 自定义站点查询；⑤ 通用：聊天记录保存复制、代码高亮、公式渲染、模块化开关。五类功能全部来自 README 一手功能清单，与 36 氪 2023 年盘点描述一致 [1][2]
多浏览器支持Chrome、Edge、Firefox、Safari（macOS）、Android 五端 + GitHub 手动安装；Manifest V3。README 安装入口 + 商店页快照；Safari 与 Android 走 wiki 安装指南而非应用商店 [1][4]
面向客群第三方产品画像定位为：普通浏览器用户、学生与研究者、开发者、内容创作者；多语言 README（英/中/日/印尼/土耳其）显示全球分发取向。中文社区口碑以「Firefox 首选 AI 插件」类推荐出现。ExtScope AI 定位分析 + 多语言 README + V2EX 用户推荐 [4][1][7]
解决痛点多站点之间切换使用 AI 的摩擦：第三方导航描述其价值为「无需在标签页或应用间切换即可在任意页面呼出 AI」；36 氪称「可以在任意页面呼出悬浮窗口与 ChatGPT 对话」。代价面：深集成需要 cookies/tabs/webRequest/<all_urls> 等高敏权限，并偶发与 Cloudflare 人机验证的兼容冲突。痛点表述 + 权限风险与兼容性问题均来自实测快照 [12][2][4]
商业模式（BYOK）完全免费、无内置付费/订阅/打赏入口（第三方检测置信 95%）。模型侧 BYOK：ChatGPT Web API（免费/Plus 账号会话）、GPT-3.5/4、Claude（会话 Key）、New Bing（Cookie）、Moonshot、Azure、自部署端点、自定义 API 地址——可与 one-api/litellm 等 OpenAI 兼容网关及 Ollama、OpenRouter 组合。README 一手 + ExtScope 付费检测；BYOK 使插件成本近乎为零，但也封闭了收入通道 [1][4]
💡 与案例墙其他翻译/对话插件的形态差异
同为浏览器 AI 插件，沉浸式翻译以「双语对照翻译」单点打穿，Chat Memo 以「对话存档记忆」切入；chatGPTBox 则是唯一把「对话、翻译、总结、视频、搜索、站点适配」六类动作全部塞进同一个浏览器原生交互层的开源项目——「广而全的全场景集成」既是其护城河（迁移成本高），也是其包袱（五端×多模型×多站点的维护面极大）。

七维深度分析

Seven Dimensions
维度分析
1. 产品功能五类集成形态（对话浮窗/划词工具/页面与视频总结/搜索引擎集成/站点适配）+ 记录管理与渲染基建，功能广度在本组浏览器 AI 插件中最高；880 fork、49 watchers 显示社区将其作二次开发底座。[1][3]
2. 面向客群全球浏览器用户（多语言 README 五语种），核心为「不想为 AI 再开一个标签页」的重度网页用户：学生研究者（论文/划词）、开发者（GitHub/StackOverflow 适配、代码解释）、内容消费者（YouTube/B 站总结）。中文社区以 Firefox 平台推荐语形式出现。[1][7]
3. 解决痛点2023 年上半年 ChatGPT 官方无插件生态，用户在网页工作流与 ChatGPT 会话间高频切换；chatGPTBox 把 AI 调用下沉到快捷键/右键/划词等浏览器原语，实现「零切换」。这一痛点随官方侧边栏与竞品-sidebar 化而稀释，是增长曲线趋平（7 日增长 0%）的结构性原因之一。[12][4]
4. 商业模式 / BYOK零收入设计：无付费点（第三方检测置信 95%）、无赞助披露。BYOK 是双刃剑——模型成本转嫁给用户，插件近乎零边际成本运行，并借 one-api/Ollama/OpenRouter 等网关形成「任意模型」兼容层；但也意味着没有收入沉淀，项目只能以兴趣/声誉驱动维持。[4][1]
5. 浏览器插件生态依赖与扩展生态深度绑定，风险集中：① 权限面极大（cookies/tabs/webRequest/<all_urls>，第三方评级 HIGH），浏览器权限政策收紧（如 MV3 限制 webRequest）可能伤及核心功能；② 目标网站改版与反爬升级直接破坏适配——2026-06 用户集中反馈 Cloudflare 人机验证冲突即为例证；③ 商店审核与下架风险常在。这是所有「深度集成」型插件的结构性宿命。[4]
6. 投入成本与维护节奏无营收、无融资、无团队披露，成本主要为个人时间：2023-03 建仓至今 3 年半，最新代码推送距实测仅 1 天，CI 自动发版降低负担；但 228 个 open issues 与「一周增长归零」的商店曲线显示维护已入稳态。bus factor = 1，作者停止维护则五端全部失修——个人开源工具的典型生命周期风险。[3][11][4]
7. 市场评价与合规口碑正面为主：Chrome 4.5/119 评（五星占 68%）、Edge 4.9、社区评价「best extension so far and its foss too」；差评集中于 Cloudflare 兼容与更新节奏诉求。合规面：MIT 开源、插件自身无支付无账号体系，监管暴露面小；风险在隐私感知——高敏权限与「能读所有网页」的能力天然伴随信任成本，作者以「可全局搜索验证不联网上传」作回应。[4][6][7][1]
