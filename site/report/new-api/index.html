案例档案

Case Profile

new-api 是国内「fork 超越上游」的标志性样本：Calcium-Ion 以个人账户在 one-api（songquanpeng 开源的 LLM API 管理 & 分发系统）基础上二次开发，功能广度与维护活跃度全面反超原版，成为大量商用 API 中转站的搭建底座[1]；项目后转入 QuantumNous 组织维护[2]。这是案例墙中首个须如实标注「组织化演进、一人属性：中」的主线案例——个人发起的爆发力与组织化之后的持续力，在本案中先后登场。

产品：New API
自托管 AI 网关（新一代大模型网关与 AI 资产管理系统）[3]：将 OpenAI、Anthropic、Google Gemini、Azure OpenAI、AWS Bedrock、Vertex AI、DeepSeek、通义千问等上游模型服务接入统一入口，在同一套控制台中管理渠道、访问权限、用量与成本[4]；官网 newapi.ai，AGPLv3 开源[2]。
信源：[2] [4] [3]
创业者：Calcium-Ion
GitHub 个人账户（2020-02-19 注册，真名未公开）[5]。以个人身份 fork one-api 二次开发发起 new-api（案例墙底稿锚点 2024-07-24）[6]，个人提交 3,113 次居全体贡献者之首（第二名 634 次）[6]；后转入 QuantumNous 组织维护。
信源：[5] [6]
一人属性口径（核心张力）
发起期个人属性强：Calcium-Ion 一人提交数 3,113 次、约为第二名的 4.9 倍[6]；组织化后：仓库归属 QuantumNous（GitHub Organization 类型实测）[2]、贡献者约 361 名[6]。案例墙收录口径如实标注：一人属性：中（已组织化）——按「个人发起→组织化收束」的演进双阶段呈现。
信源：[2] [6]
商业与治理
开源本体免费（AGPLv3 + 第 7 节附加署名与原项目链接条款，不接受义务者可联系项目方获取商业许可）[7][8]；无公开融资、营收信息（未检索到公开信息）；成功迹象以 GitHub 生态数据与中转站生态采用度为口径[2]。
信源：[2] [7] [8]

创业路径复盘

Key Turns
转折一：站在 one-api 肩膀上 fork——不重造轮子，只做增量碾压
Calcium-Ion 没有从零写一个网关，而是 fork 已被验证的上游 one-api 并保持数据库兼容，让存量用户可平滑迁移[8]。增量全部打在上游的薄弱处：OpenAI 兼容单一格式升级为 OpenAI / Claude / Gemini 三格式互转，兑换码升级为易支付 / Stripe 在线支付，新增 Rerank、Midjourney、Suno、Embeddings、Realtime 等接口，UI 与数据看板现代化[8]。同时把协议从 MIT 改为 AGPLv3+第 7 节附加条款——既以 copyleft 防止闭源套壳，又为商业许可留出变现通道[8]。
信源：[8] [4]
转折二：不做产品，做生态的「底座」
new-api 的真正杠杆不是终端用户，而是「站长」群体：2024-2025 年中转站（卖 API 调用额度的服务商）批量涌现时，大量商用站点选择以 new-api 为底座搭建[1]——统一适配、令牌分组倍率、在线充值、用量看板恰好是「开一家 API 中转店」所需的全部柜台组件[8]。当一门生意进入名人带货阶段（孙宇晨、傅盛 2026-05 相继入局）[10]，其背后的开店工具链也随之水涨船高。生态位的价值超过了产品本身的直接变现。
信源：[1] [10] [8]
转折三：个人项目 → QuantumNous 组织——「一人公司」叙事的边界
Calcium-Ion 以一人之力完成了 fork 后的原始积累（3,113 次提交居首）[6]，但当项目成为数以千计站点依赖的基础设施后，个人账户的维护带宽成为单点风险——转入 QuantumNous 组织、接受约 361 名贡献者的社区协作[2][6]，是开源治理意义上的「团队化」。这也正是案例墙将其一人属性标注为「中」的原因：本案的价值不在于「一个人做到了多大」，而在于完整展示了个人开源项目长成公共基础设施后的组织化必然。
信源：[6] [2]

将本项目作为面向公众的生成式 AI 服务或 API 转售服务运营时，使用者应先完成备案、内容安全、实名、日志留存、税务、支付和上游授权等合规义务。

产品与商业模式

Product & Business
维度内容信源
产品功能统一适配多模型上游（OpenAI / Anthropic / Gemini / Azure / Bedrock / Vertex / DeepSeek / 通义等）[4]；OpenAI / Claude / Gemini 三格式互转；渠道加权随机、失败重试、故障渠道自动禁用；令牌分组与模型倍率；按量 / 按次 / 缓存计费；兑换码 + 易支付 / Stripe 在线充值；数据看板与插件市场[4][8]
与 one-api 的差异协议 MIT → AGPLv3（含第 7 节附加署名与原项目链接条款）；接口 OpenAI 兼容 → 多格式互转；充值兑换码 → 在线支付；新增 Rerank / Midjourney / Suno / Embeddings / Realtime 接口；认证体系改为 OIDC + Discord / LinuxDO / Telegram；兼容原 One API 数据库可平滑迁移；维护更活跃[8]
生态位国内 API 中转站生态的开源底座之一（fork 系）：中转站站长以之搭建商用「卖 Token」站点；同时覆盖团队私有化网关场景（组织内部鉴权、用量统计、成本核算）[1][4]
面向客群个人开发者与小团队（自托管私有部署、Docker 一键起）[13]；中转站站长（二次分发运营）[1]；企业与 Agent 团队（多模型接入统一入口）[4][13][4]
解决痛点各厂商 API 格式互不相同，多模型接入时调试、统计、计费繁琐——new-api 在中间做格式转换与统一管理，切上游时客户端零改动；对「开店」人群，则把 key 管理、额度、计费、收款打包成开箱即用的柜台[4][14]
商业模式开源本体免费；AGPLv3 义务不接受者可联系项目方获取商业许可（协议层面的变现通道）[8]；面向公众的转售运营需自行完成备案、实名、税务、上游授权等义务（责任下沉）[4]；项目方自身营收未检索到公开信息[8][4]

维度分析信源

new-api 展示了 OPC 模式在基础设施赛道的完整生命周期：个人以 fork 完成低成本冷启动（复用上游兼容性换迁移友好）→ 以增量功能密度实现反超（51.8k★ vs 上游 37.4k★）→ 生态位兑现（中转站开店柜台）→ 组织化收束（QuantumNous + 361 贡献者）。它与作品型 OPC（如《归墟》）互为镜像：作品型的天花板是个人审美的稀缺性，基础设施型的天花板则是公共依赖度——而公共依赖度最终必然溢出「一人」的边界。
