案例档案

Case Profile

AIClient2API（原名 AIClient-2-API，社区简称 A2）是 2025 年 7 月上线的开源基础设施项目：把 Gemini CLI、OpenAI Codex、AWS Kiro、Google Antigravity、Grok 等「仅限客户端内使用」的大模型请求进行模拟与协议转换，统一封装为本地 OpenAI 兼容接口——任何支持 OpenAI 协议的工具（Cherry Studio、NextChat、Cline、Claude Code 等）由此都能调用这些原本「锁在客户端里」的模型。它是中文开发者社区「客户端协议反代」赛道目前辨识度最高的个人项目之一。

项目
JavaScript 编写、GPL-3.0 开源、Node.js ≥ 20 运行；仓库创建于 2025-07-20，现名 justlovemaki/AIClient2API（旧名 AIClient-2-API 访问自动重定向）；提供中/英/日三语 README、官方文档站与 Docker 镜像分发。

创业路径复盘

Key Turns
转折一：投稿阮一峰周刊，一个月完成冷启动
仓库 2025-07-20 创建，8 月 1 日即进入阮一峰科技爱好者周刊第 359 期的工具推荐栏——投稿人正是 justlovemaki 本人。对一个面向中文开发者的工具型开源项目而言，周刊是性价比极高的冷启动通道：不需要媒体人脉，只需要在正确的时间提交一个能一句话讲清价值的东西。这是本案「一人公司」获客方式的最清晰切片。
信源：[1] [5]
转折二：卡位「客户端协议反代」——不做聚合，做模拟
LLM API 网关赛道当时已有 one-api、new-api 等头部项目，但它们聚合的是「官方付费 API」。本案选择了完全不同的缝隙：借客户端的 OAuth 凭据与请求特征，把「只能在客户端里用」的免费/订阅额度转成标准 API。技术媒体 apifox 的横评将本案与 CLIProxyAPI、Antigravity-Manager 并列为反代三杰，并概括其定位——「基于 Node.js 构建的综合性代理项目，主打协议转换的灵活性」。赛道卡位的差异化，是一个 8.9k★ 项目能在 50k★ 级竞品阴影下立足的根本原因。
信源：[10]
转折三：灰色地带的生存术——号池、指纹伪造与政策追逐
上游平台随时可能封禁：项目的应对是一套工程化的「对抗体系」——账号池轮询与故障转移摊薄单号风险；内置 TLS Sidecar（Go uTLS）模拟浏览器指纹，绕过 Grok 等服务的 Cloudflare 403 拦截；README 则主动提示「Kiro 服务使用政策已更新，请访问官方网站查看最新使用限制和条款」。版本高频迭代（近期一个月五版）本质上是与上游协议、风控规则的无声竞赛——这也是该赛道无法「做完就躺」的结构性原因。
信源：[4] [7]

产品与商业模式

Product & Business
维度内容说明
技术原理客户端协议反代模拟 Gemini CLI / Qwen Code / Kiro 等客户端请求，读取本地 OAuth 凭据文件代为转发；ConverterFactory 层实现 OpenAI / Claude / Gemini 三大协议智能互转；内置 TLS Sidecar（Go uTLS）模拟浏览器指纹以绕过 Cloudflare 403 [4][10]
支持的客户端矩阵Antigravity、OpenAI Codex、Grok CLI、AWS Kiro、Gemini CLI、Qwen Code + OpenAI/Claude/自定义 Provider输出统一为 OpenAI 兼容接口（兼 Claude / Gemini 协议）；模型覆盖 Claude Opus/Sonnet、Gemini Pro、GPT 系、Grok、Kimi、MiniMax 等 [1][4]
部署方式Docker（一键启动）+ npm 包 + Node.js 直跑Docker 镜像 justlikemaki/aiclient-2-api（Web UI 端口 3000 + 各客户端 OAuth 回调端口）；npm 分发渠道 @mseep/aiclient2api；官方文档站提供安装/API/高级配置/开发四类指南 [3][11][12]
面向客群开发者 / AI Agent 重度用户Cherry Studio、NextChat、Cline 等主流工具用户，以及 Claude Code、OpenClaw 等 Agent 场景；「AI 优先设计」是 README 明示的产品原则 [8][4]
解决痛点无 API 的客户端能力复用大量免费/订阅额度只存在于客户端内（如 Kiro 新用户积分、Antigravity 内置 Gemini/Claude），无法接入自动化与业务系统——本案将其「解放」为标准 API，省去按量计费成本 [10][7]

商业模式拆解

项目本体完全免费开源（GPL-3.0），无付费墙、无托管云服务。README 设有赞助商体系，目前公示的活跃赞助方为 API 中转服务商 PackyCode（用户以优惠码 AIClient2API 注册充值可享 10% 折扣，即典型的返佣合作），历史赞助位还包括 APIKEY.FUN、VisionCoder、AICodeMirror、Atlas Cloud 等——均为项目目标用户高频消费的「AI 中转/算力服务商」。换言之，可见的变现闭环是：工具聚拢开发者 → 赞助位 + 返佣链接变现，项目方自身不碰转卖额度的灰色环节。除此之外的商业化信息未检索到公开披露。

成本侧为典型的个人开源项目结构：无办公室、无雇员，主要投入是开发者本人的时间——以及为追赶上游协议变化持续投入的工程精力（43 位社区贡献者的 PR 协作摊薄了部分维护负担）[6]。

本案的差异化定位清晰：one-api / new-api 这类合规网关解决「有 API 的人怎么管好 API」，本案解决「没 API 的额度怎么变出 API」——后者直接踩在平台服务条款的边界线上，也因此体量小一个数量级（8.9k★ vs 37-51k★）、迭代频率却远高于合规网关（需持续追赶上游协议与风控变化）。同一赛道内，「合规聚合」与「协议反代」构成了灰色光谱的两端：前者做大了商业化（new-api 大量商用中转站底座），后者做大了个人影响力与社区声量，但在商业化上明显更谨慎。

七维深度分析

Seven Dimensions
维度分析
1. 产品功能自托管多协议 AI 网关：客户端请求模拟 + OAuth 凭据代理 + OpenAI/Claude/Gemini 三协议互转 + 账号池调度（轮询/故障转移/降级）+ Web UI 管理台 + 插件体系（v3.6.5 起需管理员签名批准）+ Docker 一键部署。[4][1]
2. 面向客群核心客群是无法/不愿直接订阅海外 API 的个人开发者与 AI Agent 重度用户（Cherry Studio、Cline、Claude Code、OpenClaw 用户）；间接客群是 seeking 低成本算力的小团队。社区教程主要面向中文开发者。[8][4]
3. 解决痛点「客户端专属额度 API 化」：Kiro 新用户赠送积分、Antigravity 内置 Gemini/Claude、Grok 客户端能力等原本锁死在 GUI 里的资源，被转换成任何应用可调用的标准接口。第三方教程将其概括为「免费撬动顶级模型」。[10][7]
4. 预估年化营收（推算，置信度 C）营收零披露。可核验的变现线索仅两类：① README 赞助商返佣位（PackyCode 优惠码等）；② 开源社区捐赠（未检索到公开金额）。项目无付费墙、无托管服务，无法支撑任何量化推算——如实标注「未检索到公开营收数据」。参照同类个人开源项目，此类项目的货币化上限通常远低于其社区声量。[4]
5. 融资进展未检索到公开信息。GitHub 资料显示为个人账号运营（40 个公开仓库），无公司主体、无团队招聘迹象；43 位外部贡献者以 PR 形式协作，属开源社区协作而非雇佣关系。[2][6]
6. 市场评价正面评价密集：阮一峰周刊工具栏目收录（2025-08）；apifox 技术横评称其「突破限制的全能转换器」「协议转换的灵活性、防封控能力强」；Trendshift 双榜第 2；CSDN 品牌专区专文推荐；官方文档站体系完整。未见权威媒体深度报道——传播全部发生在开发者社区内部。[5][10][6][12]
7. 投入成本与合规风险（本案核心争议）① 服务条款冲突（结构性风险）：反代客户端协议、复用客户端专属额度的行为普遍违反上游平台 ToS——技术媒体原文警示「这种反向代理提取官方免费额度的行为不符合服务条款，平台风控敏锐，检测到异常并发流量会导致账号封禁，务必使用测试小号，绝对不要绑定个人主力账号」。[10]
② 上游封号风险：项目 README 自己提示「Kiro 服务使用政策已更新，请查看最新使用限制和条款」；灰产调研文披露上游 Kiro Power 套餐 $200/月与淘宝 19 元成品号之间存在 80 倍差价空间，平台封号周期短至 3 天。[4][7]
③ 技术对抗的敏感性：内置 Go uTLS 指纹伪造绕过 Cloudflare 检测，属对上游风控的主动对抗设计，一旦上游升级检测，功能与账号存活都会受冲击。[4]
④ 法律层面：未检索到针对项目方本身的公开诉讼、行政处罚或 GitHub 下架处置；中国境内亦未检索到公开监管口径点名此类工具。风险敞口集中于「上游平台处置 + 下游滥用连坐」。

争议与不确定性

Open Questions
⚠️ 核心争议：反代工具的「中性开源」与下游灰产滥用
① 灰色产业链被指以其为底层技术：第三方调研文（信息来自社区调研与公开资料整理，非亲历）描述了一条「上游批量黑卡注册 Kiro Power 账号 → 中游 AIClient-2-API 把账号转成 API 接口 → 下游以 $0.2/刀转卖 Claude API（正价 $1.35/刀）」的利益链，并提及有 NodeSeek 卖家自曝「一天流水 3K、大客户 1-2 万」——该流水属下游转卖卖家而非项目方收入，引用时不可混淆。[7]
