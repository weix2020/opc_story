案例档案

Case Profile

claude-code-router（社区简称 CCR）是一个把 Claude Code 的请求劫持并转发到任意大模型供应商的本地开源网关：开发者无需 Anthropic 官方账号，即可用 DeepSeek、Kimi、通义、Gemini 等模型驱动 Claude Code 的完整体验。它是国内「AI 开发者工具」赛道「厂商赞助型开源 OPC」的代表样本——项目免费开源（MIT），收入来自厂商赞助与生态位本身。

项目
本地模型网关与控制平面：为 Claude Code 及 Codex、Grok CLI、Kimi CLI、OpenCode 等十余种编程 Agent 提供「一个稳定的本地端点」，在其后统一管理供应商、模型、账号、路由规则与工具；TypeScript 编写，MIT 许可，支持桌面 App、npm CLI 与 Docker 三种形态。
信源：[2] [1]
创业者
musistudio（GitHub 昵称显示为「musi」，坐标杭州，个人简介 Focusing on AI，2016 年注册 GitHub，个人主页公开仓库 194 个、粉丝 642）[1]；真名未公开，未检索到公开实名报道。

GitHub 仓库创建于 2025-02-25——即 Anthropic 官方 Claude Code 发布次日；作者自述当天即完成对 Claude Code 的逆向工程，找到 ANTHROPIC_BASE_URL 环境变量劫持点，次日产出首条可回溯提交（2025-02-26，Bypass auth）。

创业路径复盘

Key Turns
转折一：把「用不上」变成「随便用」——速度即生态位
Claude Code 2025-02-24 发布，musistudio 次日即完成逆向并建仓。这个「时差」决定了项目卡位：在官方区域封锁、注册排队、支付门槛三重限制下，第一批想用 Claude Code 的大陆开发者几乎必然经过 CCR 的路径——用环境变量把请求重定向到本地网关，再用国产模型顶上。作者博客完整披露了逆向过程（npm 包定位 → 反混淆 → DevTools 断点 → 搜 api.anthropic.com 关键词），本身就是一份「一人逆向工程方法论」。
信源：[3]
转折二：跟着模型能力演进重构，而非固守首版架构
初版四角色（router/tool/think/coder）因轻量模型调度不准而失败，作者没有硬扛，而是在 2025-05-28 DeepSeek-R1 支持 Function Call 后整体重构为 default/background/think/longContext 的「按任务类型分流」机制——后台杂事给本地小模型、推理给 R1、长上下文用 tiktoken 实时测算后自动切换。这套机制后来被火山引擎教程原文转述为「根据需求将请求路由到不同的模型（如后台任务、思考、长上下文）」，成为项目的技术名片。
信源：[3] [4]
转折三：从单点网关到「厂商赞助生态」——开源 OPC 的变现样本
CCR 的商业闭环不靠卖 License，而是靠生态位收租：README 收款位覆盖 Ko-fi、PayPal、支付宝、微信；「Our Sponsors」厂商位现有 Z智谱、AIHubmix、BurnCloud、302.AI、RunAPI、TeamoRouter、code0.ai、claudeapi、七牛云 AI、Fenno.ai、Unity2.Ai、无限星河等 12 家，其中多家链接带 aff 返佣参数或 utm 合作标记——模型供应商向「流量入口」付费。Kimi 更曾以具名赞助方身份写入 README 快照并成为内置预设。2026-10 改版后，CCR 从「Claude Code 专用」扩张为「所有编程 Agent 的本地控制平面」，把生态位从单一工具面抬升为基础设施面。
信源：[2] [8]

这个项目提供了一种在 Anthropic 区域限制下运行 Claude Code 的务实路径，在成本、性能与可定制性之间取得平衡。话虽如此，如果条件允许，官方 Max Plan 仍是最佳体验。

—— musistudio，项目自述博客《Project Motivation and Principles》（意译），原文见 [3]

产品与商业模式

Product & Business
维度机制与事实信源
路由原理利用 Claude Code 尊重 ANTHROPIC_BASE_URL 环境变量的特性，由 Express.js 在本地实现 /v1/messages 端点；中间件（transformer）完成 Anthropic Messages 格式与各家 API 格式的双向转换，支持按模型改写请求（prompt 调优）。不改动 Claude Code 源码，可随官方更新受益。[3]
供应商分流机制v1 定型四角色路由：default（通用兜底）/ background（后台轻任务，作者路由至本地 ollama）/ think（推理规划，接 DeepSeek-R1）/ longContext（tiktoken 实时计长，超 32K 自动切换）。v3 改版后扩展为条件路由、有序故障转移（fallback）、请求重写、重试与凭证池。[3] [2]
内置 provider 与赞助生态内置预设覆盖 OpenAI Chat/Responses、Anthropic Messages、Gemini、OpenRouter、DeepSeek、SiliconFlow、Moonshot / Kimi Code、Mistral、Z.AI、百炼等，并支持自定义兼容端点；赞助位 12 家厂商 + 社区赞助者名单，Ko-fi/PayPal/支付宝/微信四通道收款。[2]
面向客群核心客群为 Claude Code 用户（尤其受区域限制与订阅成本约束的大陆开发者）；v3 之后扩展至 Codex、Grok CLI、Kimi CLI、Kilo Code、OpenCode、Pi、ZCode、WorkBuddy 等全部主流编程 Agent 用户——「一个稳定的本地端点」。[2] [4]
解决痛点三重痛点叠加：① 官方订阅贵且有 5 小时限额（社区原声「max 还是有点贵」）；② Anthropic 封锁中国大陆，注册/支付/连通全链路受阻；③ 国产模型强且便宜——作者实测 DeepSeek-V3 成本不足 Claude 3.5 Sonnet 十分之一。CCR 让「Claude Code 的壳 + 国产模型的芯」成为可能。[3] [7] [13]
商业模式软件本身 MIT 免费开源；收入 = 厂商赞助位（部分含返佣参数）+ 社区打赏 + 桌面版分发（ccrdesk.top）。未检索到公开营收数据。[2] [1]
💡 商业模式要点：开源工具的「厂商赞助」曲线
与 one-api / new-api 的「中转站底座」不同，CCR 的赞助方不只是 API 二道贩子，还包括智谱、Moonshot（Kimi）等模型原厂——它们赞助的不是代码，而是「Claude Code 存量用户的模型选择权」。当一个开源工具成为用户换模型的默认入口，原厂就有动机付费上车。这是 2026 年国内开源 OPC 中少见的「上游厂商付费」结构。

Seven Dimensions
维度分析信源
1. 产品功能本地模型网关 + 控制平面：格式转换（Anthropic ↔ 各家 API）、按任务类型分流（默认/后台/思考/长上下文）、条件路由与故障转移、凭证池、动态切换（/model）、GitHub Actions 集成、插件系统；v3 后扩展至 10+ 编程 Agent 并提供桌面 App。[3] [2] [4]

依赖风险：建立在对手地基上的房子
CCR 的全部价值依附于 Claude Code 的持续存在与其环境变量机制的开放性。2026 年起风向已变：Kimi 官方文档直接给出「在 Claude Code 中使用 Kimi」的 Anthropic 兼容端点配置[6]——当原厂自己提供官方通道，民间网关的转换价值被部分吸收。CCR 的应对是横向扩张（支持 10+ Agent 成为通用控制平面），但这条路上它要面对 new-api 等组织化对手的正面竞争。

本案的样本价值
CCR 证明了 OPC 在「基础设施层」的另一种可能：不需要融资、不需要卖订阅，只要在巨头封锁的缝隙里做出一个足够刚需的入口，上游厂商会自己走过来付钱。它同时是「单人开源项目天花板与天花板之下的脆弱性」的合体样本——38k 星标与 1,200 未处理 issue、阶段性赞助与随时可能被官方通道替代的生态位并存。对想复制此路的一人开发者，本案给出的公式是：速度（发布次日逆向）× 真实痛点（区域封锁+成本）× 生态位经营（让供应商有理由赞助），以及一条底线——把逆向过程与技术理由全部公开写下来，让项目在灰色地带获得社区共识护航。
