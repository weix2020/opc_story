案例档案

Case Profile

one-api 是 2023 年 4 月由个人开发者 songquanpeng 开源、用 Go 编写的「LLM API 管理 & 分发系统」：以标准的 OpenAI API 格式统一访问所有大模型，支持令牌管理、额度控制与二次分发，单可执行文件、提供 Docker 镜像、一键部署[1][2]。它不直接向用户收费、不做公司化运营，却成为此后两年国内「API 中转站」生态几乎绕不开的地基——下游分支 new-api 的星标已反超本体[3][4]。

项目
GitHub 仓库 songquanpeng/one-api：MIT 协议，主仓库描述为「LLM API 管理 & 分发系统」，支持 OpenAI、Azure、Anthropic Claude、Google Gemini、DeepSeek、字节豆包、ChatGLM、文心一言、讯飞星火、通义千问、360 智脑、腾讯混元等主流模型；项目主页 oneapi.justsong.cn，在线演示站 openai.justsong.cn。
信源：[1] [2]
创业者
songquanpeng，GitHub 显示名 JustSong（社区惯称 justsong）。GitHub 档案：所在地上海，公司栏标注 South China University of Technology（华南理工大学），粉丝 1,962、公开仓库 105 个，账号 2018-06-06 注册；个人网站 iamazing.cn / justsong.cn。真实姓名未公开确认，本报告以网名行文。
信源：[5] [6]
项目性质
个人开源公共品：英文技术媒体报道其「Funding: None publicly disclosed; community-maintained」（无公开融资、社区维护），作者通过 iamazing.cn 的「赞赏支持」页接受捐赠，未检索到公司注册、付费版或商业化主体的公开信息。
信源：[7] [2] [6]
成功迹象
GitHub 37,420★ / 6,894 forks（2026-11-13 API 实测）[1]；案例墙收录口径为「国内 AI 中转站生态事实标准」——第三方对比文称其为「自建 Token 中转站的常用方案」，下游 new-api 被大量商用中转站用作底座，均传导自 one-api 的能力与数据模型。
信源：[1] [4] [8]

创业路径复盘

Key Turns
转折一：从「二手 API 卖家不稳定」的个人痛点，到公共基础设施
2023 年春，国内开发者访问 OpenAI API 困难，市场上充斥稳定性存疑的「二手 API 卖家」。songquanpeng 的解法不是再做一个卖家，而是把「聚合 + 负载均衡 + 密钥分发」做成开箱即用的开源工具——初版即支持接入多家第三方中转渠道并自动分流。作者在项目页写明双重定位：既是稳定的 API 后端，「或者你也想当 API 卖家，那么本项目也可以帮助你快速搭建一个 API 服务」。这种「卖铲子」而非「卖水」的定位，让 one-api 从一开始就站在了生态的分发层。
信源：[6] [2]
转折二：MIT 协议 + 单二进制 + Docker 的「零门槛」策略
one-api 全程坚持 MIT 协议（商用与闭源二开几乎不受限）、单可执行文件、SQLite 开箱即用、一条 docker run 命令部署。第三方对比将其总结为「中小团队做 LLM 资源整合的最省事方案」——不需要懂路由、不需要自己写计费逻辑。这一零门槛组合客观上成为中转站生态爆发的助推器：任何人都能在几分钟内把「聚合 API」变成「对外卖 API」的服务，而无需向后 surrender 任何权利（对比下游 new-api 选择的 AGPLv3 附加条款路线）。
信源：[2] [4] [9]
转折三：不收费、不融资、不公司化——价值全部外溢给生态
无公开融资、无付费版本，变现路径止步于个人网站「赞赏支持」。代价是维护能力受限于个人精力：最新版本停在 2025-02，最后 push 停在 2026-01，英文媒体直言「无机构支持下，长期维护、安全补丁与供应商 API 适配全依赖志愿者」；馈赠则是整个下游生态——new-api 在其数据模型与代码底座上长到 51,855★、反超本体，成为商用中转站的主流底座。one-api 完成了「个人项目长成行业地基」的全过程，却几乎未曾从地基上的商业大厦收取租金。
信源：[7] [1] [6] [3] [4]

由于众所周知的原因，OpenAI 的 API 在国内访问困难，因此目前出现了一批二手 API 卖家，但是这些二手 API 卖家的稳定性存疑。……或者你也想当 API 卖家，那么本项目也可以帮助你快速搭建一个 API 服务。

—— songquanpeng，《One API》项目介绍页（iamazing.cn，2023-04-23），转引自 [6]

七维深度分析

Seven Dimensions
维度分析信源
1. 产品功能完整覆盖「聚合—管理—分发」三层：28+ 供应商统一适配、负载均衡与失败重试、令牌/额度/IP/模型范围控制、兑换码充值、分组倍率、模型映射、多机部署、管理 API；单二进制 + Docker + SQLite/MySQL/PG，从个人玩具到小规模生产均可承载[2]
2. 生态位（中转站事实标准）第三方对比文将其定性为「自建 Token 中转站的常用方案」；下游 new-api 为大量商用中转站底座且兼容 one-api 数据库（迁移路径顺畅）；生态长文显示中转站已成产业链（上游号商—中游面板—下游分销），面板级工具即 one-api/new-api 一系的范式。多源旁证成立，但无权威统计直接点名[4] [3] [10]
3. 面向客群三层客群：自用型个人开发者（聚合自己的 Key）、中小团队（统一 LLM 网关，评价称「UI 直接给产品经理用」）、中转站运营者（白标 API 卖给客户）；部署教程类内容（CSDN 等）的持续产出显示非专业用户占比可观[9] [10] [6]
4. 解决痛点核心痛点是「provider fragmentation」：每接一家模型就要管理一套 SDK、认证流与账单。one-api 用一个 OpenAI 兼容端点抹平差异，叠加国内访问海外 API 困难的特殊环境，恰逢 2023 年国产大模型爆发期——「统一适配国产模型」使其成为横跨中西生态的稀缺汇合点[7] [2] [6]
5. 商业化与营收（置信度 C）零营收披露：无付费版、无融资、无公司主体公开信息，变现仅见个人站赞赏入口。可推断的商业选项（企业版托管、支持服务）均未落地。作为 OPC 样本，其「收入」维度无数据可分析——这是与案例墙内收费型案例（如 ChatWise、Bob）最大的结构差异[7] [6] [2]
6. 开源维护可持续性（一人维护的更新节奏）实测数据显示明显的节奏滑坡：最新 release v0.6.10 停在 2025-02-02，最后 push 2026-01-09，此后 10 个月无更新，open issues 堆积至 1,045；第三方对比文 2026-07 将其活跃度评为「在维护」（弱于 new-api 的「活跃」）；英文媒体早在 2026-05 即警告「无机构支持，长期维护、安全补丁与供应商适配依赖志愿者」。100+ 贡献者存在，但架构决策与发版高度集中于一人[1] [4] [7]
7. 合规灰区（API 二次分发）one-api 的核心场景「key 二次分发」正处于灰色地带：作者在 README 顶部主动置入合规声明——须遵循 OpenAI 使用条款与《生成式人工智能服务管理暂行办法》，「请勿对中国地区公众提供一切未经备案的生成式人工智能服务」；生态长文指出转卖 API 在 Anthropic 服务条款中被禁止（国内无对应条款，风险为封号与支付冻结），并记录了中转站生态的乱象：媒体转述的 CISPA 论文审计称 17 家主流中转站近 45% 存在模型造假，叠加流量虚扣、卷款跑路。工具本身中立，但其最大用例处于上游 ToS 的禁区与国内备案要求的边缘——作者以免责声明「切割」，而非下架功能[2] [8]

争议与不确定性

Open Questions
⚠️ 三项风险与两处留白（截至 2026-11-13 检索）
① 维护停滞风险：代码停更 10 个月、版本停更 21 个月、1,045 个 open issues——若作者持续投入意愿下降，安全补丁与新供应商适配将依赖社区接棒，这正是媒体点名的「无机构支持」结构性风险[1][7]。② 生态重心转移：下游 new-api 在功能（多格式互转、在线支付、数据看板）与活跃度上全面反超，中转站新建部署事实上正向 new-api 迁移[4][3]。③ 合规外溢风险：上游模型商 ToS 禁止转卖、国内生成式 AI 备案要求趋严，中转站生态的收紧会直接压缩 one-api 的核心用例[8][2]。留白：作者真实身份与职业状态未公开确认；Docker 拉取总量、实际部署站点数等生态规模数据无公开可核验口径。
📝 口径说明

本案的样本价值：OPC 的另一种形态——「零收入的生态型一人公司」
案例墙内多数 OPC 以营收或用户量证明自己，one-api 提供了另一种证明方式：一个人的项目成为整个行业生态的地基。它没有收入、没有融资、没有公司，却定义了中文世界的 LLM 网关范式，供养出星标反超自己的下游（new-api 51,855★）与一个规模可观的产业带（中转站生态）。同时它也是一面警示牌：不商业化的公共品最终受制于单人维护的精力天花板，「事实标准」的护城河会随维护停滞而被 fork 蚕食——2026 年的 one-api 正站在这条曲线的拐点上。
