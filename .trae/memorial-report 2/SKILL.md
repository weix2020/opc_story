# 专业报告写作规范 · Report Writing Standard

> **铁则（先落盘，后校准）**：凡写长报告，必先落盘并上传，**再**做编号校准与收尾。校准脚本须先 `try/except` 并打印断言。
> **历史教训**：2026-11-02 一次因收尾脚本 `IndexError` 令整役上下文撑爆（累计 8 次 overflow），实属"为交付而伤交付"。

---

## 〇、适用范围与触发

凡调研、撰写、汇编、舆情分析、政策解读、行业报告、研判、年报、人物档案等**任何需要交付文本**的任务，皆适用本规范。

**对外表述口径**：正文采用中性、专业、可公开的表述；不使用任何特定人设称谓、角色身份或内部玩笑；引语与案例一律以真实身份呈现。

**不适用**：内部便笺、纯闲聊、无引用的短答。

## 一、交付流水线（六步法）

```
1. 调研 → web_search / web_fetch 多源交叉（可配合 web-tools-guide 一类的工具分流指南：search→fetch→CLI→browser）
       ↓
2. 评级 → 按 §5.2 矩阵为每条来源打 A+/A/B+/B/C+/C
       ↓
3. 标色 → 按 §5.1 三级标签决定 .verified / .cross / .partial
       ↓
4. 撰写 → 落盘 <slug>-v<ver>.html，插入 <sup class="cite xxx">[n]</sup>，编号连续递增
       ↓
5. 汇编 → 文末 §5.4 逐条填齐 + 事实核查小结
       ↓
6. 校验+发布 → 先落盘 → 再校准（§6 Checklist 全过）→ 上传 → HTTP 200 验证 → 交付最终读者
```

**取证纪律**：
- 学者专家须**实名标注**（姓名 + 职务 + 机构）；无实名者仅作"业内人士认为"，不入专家卡片。
- 政策类报告须含**至少 1 个真实受众 / 缴存人个案**（带名字、城市、身份），体现"政策的真实获得感"。
- 严禁伪造数据、伪造链接、伪造引用。

## 三、章节组件库（7 块，灵活组装）

> 章节部分**灵活安排为要**，未必非要有归某七章之限。按议题可得性实际选用、重组、增删。

| 序号 | 组件名 | 适用场景 | 核心呈现 |
|---|---|---|---|
| 1 | **政策要点 / 主题概述** | 政策类、议题类、事件类报道 | 卡片化核心要素 |
| 2 | **市场反应 / 数据呈现** | 有数据可考的议题 | 表格 + 数字 |
| 3 | **舆论回声 / 各方声音** | 公共事件、社会议题 | 时间线 + 三极卡片 |
| 4 | **资本博弈 / 行业动态** | 涉及资本市场、行业链 | 个股表 + 引文 |
| 5 | **专家观点 / 权威解读** | 政策类、专业议题 | 6 卡片横向罗列 |
| 6 | **形势判断 / 风险与建议** | 总结性、决策性 | 一句话定性 + 三重信号 + 观察窗口 + 风险清单 |
| 7 | **资料来源、网址与事实核查** | **所有报告必备，不可省略** | 编号参考资料 + 核验标签 + 核查流程小结 |

**灵活原则**：
- 第 7 项为**必备章节**，不可省略。
- 政策类报告另须含"市场反应与专家评论"（★，见 §四）。
- 其余 6 项任意选用、重组、增删。
- 序号依次用壹/贰/叁/肆/伍/陆/柒 中相应汉字，**不连续亦可**。
- 纯事实整理（年报、人物档案）可仅留 1 + 7；深度调查可全部 7 项上阵。
- **报告长度与章节数量不挂钩**：简报 3 章，详报 10+ 章。

## 四、政策类强制合并章：「市场反应与专家评论」

政策类报告须将 §三 的 #2（市场反应/数据呈现）、#3（舆论回声/各方声音）、#5（专家观点/权威解读）**合并为一章**，下设**五个固定子节**：

1. **地方落地节奏表**
2. **学者专家卡片**（姓名 / 机构 / 引语；无实名者不入此节）
3. **行业研究机构观点**（含数据）
4. **缴存人 / 受众声音**（含至少 1 个真实个案：名字、城市、身份）
5. **房企 / 行业反应**

此节下所引证据须在文末资料来源中以**独立条目**列出，并标注事实核查标签。

## 五、引用与索引规范（事实核查体系）

> **颜色即信源等级，编号即核验状态。**
> 核心承诺：每一处引用，都可追、可查、可信。

### 5.1 三级核验标签

文中上标 `<sup>` 与文末徽章 `[n]` **必须同色、同编号、同含义**。

| 颜色 | CSS 类 | 等级 | 含义 | 触发条件 |
|---|---|---|---|---|
| 🟢 绿色 | `.verified` | **已核验** | ≥2 独立信源交叉验证 + 原文回溯 | 默认目标；多数引用应落此级 |
| 🔵 蓝色 | `.cross` | **多源印证** | 单一权威媒体但可二次确认 | 独立信源仅 1 家，但为 A+/A 级 |
| 🟡 琥珀色 | `.partial` | **部分映证** | 含合理推断 / 转述 / 摘要成分 | 转述、自媒体引述、合并多源 |

**铁律**：颜色升级从严，降级从宽。宁可标 `.partial` 不夸大；不能凭单一 C 级源贴 `.verified`。

### 5.2 信源评级矩阵（六级）

| 评级 | 类型 | 范例 |
|---|---|---|
| **A+** | 政府部门、央级官方媒体、官方文件 | 国务院、央行、证监会、新华社、人民日报、官方公告原文 |
| **A** | 头部权威研究机构、主流财经媒体、专业智库 | 中金、中信证券、财新、第一财经、彭博、路透 |
| **B+** | 持牌券商研报、上市公司公告、权威财经数据平台 | 申万宏源研报、巨潮资讯网、Wind、东方财富 Choice |
| **B** | 主流门户财经频道、知名行业自媒体 | 界面、澎湃、36 氪、虎嗅、钛媒体 |
| **C+** | 实名作者观察、行业 KOL 观点 | 署名专栏作者、知名分析师个人公号 |
| **C** | 自媒体解读、社交平台截图 | 微博、微信公众号未署名帖、Reddit、知乎匿名 |

**评级细则**：
- 同源多次出现，按最高评级计。
- 转述链超过 2 层，自降一级（如 A → B+）。
- 含个人评论 / 推断成分，强制入 `.partial`，即使源为 A+。
- 学术论文：SCI/SSCI 同行评议 ≈ A+；预印本 / 工作论文 ≈ A。

**白名单锚点**（默认 A+/A 评级起点，白名单外按矩阵逐条评估）：
`gov.cn` `www.gov.cn` `stats.gov.cn` `mof.gov.cn` `csrc.gov.cn` `pboc.gov.cn` `xinhuanet.com` `people.com.cn` `cctv.com` `news.cn` `caixin.com` `yicai.com` `stcn.com` `cls.cn` `cnstock.com` `bloomberg.com` `reuters.com` `ft.com` `wsj.com` `nytimes.com` `sse.com.cn` `szse.cn` `hkex.com.hk` `sec.gov` `goldmansachs.com` `morganstanley.com` `cicc.com.cn` `citics.com` `gtja.com` `chinaventure.com.cn` `zero2ipo.com.cn` `iyiou.com` `36kr.com`

### 5.3 文中上标规范

```html
已核验：<sup class="cite verified">[1]</sup>
多源印证：<sup class="cite cross">[2]</sup>
部分映证：<sup class="cite partial">[3]</sup>
```

- **无边框**（仅背景色 + 字色），11px / Georgia 衬线 / font-weight 700
- 序号 `n` 从 `[1]` 起**连续递增**，不跳号、不重号
- 同一处事实可引多源 → 写 `[1][2]`，**不写** `[1,2]`
- 必须可点击 → 跳转文末 `#ref-n` 锚点；文末锚点 id 形如 `id="ref-1"`

### 5.4 文末资料来源条目规范

```html
<li id="ref-1" class="src">
  <div class="sh">
    <span class="idx verified">[1]</span>
    <span class="rt">A+</span>
    <span class="st">政府文件</span>
  </div>
  <div class="ti">国务院关于……的通知（国发〔2026〕XX 号）</div>
  <div class="mt">
    <b>来源：</b>中国政府网　<b>发布日期：</b>2026-08-12<br>
    <a href="https://www.gov.cn/..." target="_blank">https://www.gov.cn/...</a>
  </div>
  <div class="note">事实核查注释：原文回溯；与新华社同日报道 [2] 相互印证</div>
</li>
```

**铁律**：
- 标题为**纯文本**，**不得**用 `[标题](链接)` 形式（链接放独立 URL 字段）。
- 必含字段：来源 / 发布日期 / 类型 / 信源评级 / 事实核查注释。
- 每条须有 `事实核查注释`（`class="note"`），说明回溯与印证情况。
- 文末须有**事实核查小结**：本期共引用 N 条，绿 X / 蓝 Y / 黄 Z，A+/A 级原文回溯完成情况。

### 5.5 引用铁律 10 条

1. 每一条事实性陈述必须有上标。无上标 = 无引用 = 不可外发。
2. 数据 / 数字 / 引语 / 政策条文 → 强制上标，不可省。
3. 常识 / 公理 / 方法论陈述 → 可不上标，但须避免与新事实混排。
4. 同一处事实可引 2—3 条，并列写作 `[1][3]`。
5. 学者专家实名入卡 → 强制 A 级源 + `.verified` 或 `.cross`。
6. 匿名引语（"业内人士认为"）→ 入 `.partial`，不入学者卡。
7. 未署名自媒体 → 强制 C 级 + `.partial`，不可贴 `.verified`。
8. 政策类报告须在"市场反应与专家评论"章下含至少 1 个真实受众个案，个案来源计入文末。
9. 链接必须可点、可打开。
10. 核查小结必须出现。

## 六、外发前 Checklist（强制 12 项）

- [ ] 所有事实句均有上标（除常识段）
- [ ] 上标编号从 `[1]` 起连续递增，无跳号、无重号
- [ ] 颜色与核验结果一致（绿/蓝/黄无错位）
- [ ] 学者专家实名标注；未实名者仅作"业内人士认为"
- [ ] 信源评级 A+/A/B+/B/C+/C 已逐条标齐
- [ ] 文末资料来源标题为**纯文本**，未用 `[标题](链接)` 形式
- [ ] 每个 URL 完整、可点、可打开
- [ ] 必填字段齐：来源 / 发布日期 / 类型 / 评级 / 核查注释
- [ ] 含事实核查小结（合计 + 三色分布 + A+/A 回溯）
- [ ] 政策类报告含"市场反应与专家评论"合并章 + 至少 1 个真实个案
- [ ] 无伪造数据 / 伪造链接 / 伪造引用
- [ ] 页脚含"本报告不构成投资建议"声明

## 七、归档与发布

| 项目 | 规范 |
|---|---|
| **存储** | 任意支持公有读的对象存储（CDN / 静态托管 / 图床），按类型分目录 |
| **路径约定** | HTML → `page/`（或 `site/`）· Markdown → `md/` · 图片 → `img/` |
| **命令示例** | `coscmd upload <local> page/<file>.html`（或 `aws s3 cp` / `rclone copy`） |
| **验收** | `curl -I` 验证 HTTP 200 |
| **回传格式** | `[报告标题 v版本号](公网URL)` —— 整行超链接，前端只见标题、点击可直达 |
| **交付内容** | 章节结构 + 公网链接 + 上版差异（如有） |

> 部署方可按自身基础设施替换存储与渠道；本规范不绑定任何特定服务。

## 八、严禁事项

- ❌ Hero 封面留任何浮饰符号或阴影
- ❌ 文末资料标题用 `[标题](链接)` 形式
- ❌ 上标索引加边框
- ❌ 编号跳号 / 重号
- ❌ 单一 C 级源贴 `.verified`
- ❌ 未署名 KOL 入学者专家卡
- ❌ 伪造数据 / 链接 / 引用
- ❌ 报告不构成投资建议（页脚声明不可省）

## 十、维护规约

- 本规范由多轮实践迭代定稿：早期确立报告版式与章节组件库，其后补充引用与索引规范，最终合铸为单一技能文档。
- 任何变更须同步更新 §五 标签矩阵与白名单，并留存修订记录。
- **改写长期记忆或索引类文件时禁用 `find` 模糊边界匹配**，一律用显式唯一锚点串；改写前先 `cp` 备份至临时目录，改写后必跑「章节完整性 + 条目数 + 全文归一化 diff」三道校验。
- 技能本体的增删改建议走提案 → 审核 → 应用的受控流程，避免直接手改线上版本。
